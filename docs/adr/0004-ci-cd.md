# ADR 0004: CI/CD pipeline and security gates

Status: accepted · Date: 2026-10-29

## Context

The repository is public and is meant to demonstrate DevSecOps practice. `main` must always build, and every change must pass the same gates.

## Decision

Trunk-based: short-lived branches, pull requests into protected `main` (required checks, linear history, no force-push, squash merge). Conventional Commits enforced on PR titles.

**`ci.yml` (every PR and push to `main`, `windows-latest`):**

| Gate       | Tool                                                                   |
| ---------- | ---------------------------------------------------------------------- |
| Format     | Prettier `--check`, `cargo fmt --check`                                |
| Lint       | ESLint, Clippy `-D warnings`                                           |
| Types      | `tsc --noEmit`                                                         |
| Unit tests | Vitest (coverage report), `cargo test`                                 |
| Build      | `tauri build --no-bundle`                                              |
| End to end | Playwright smoke test on the built app (local release gate, see below) |

**`security.yml` (every PR, push to `main`, weekly schedule):**

| Gate         | Tool                                                                                   | Fails on                   |
| ------------ | -------------------------------------------------------------------------------------- | -------------------------- |
| SAST         | CodeQL (JavaScript/TypeScript, Rust)                                                   | any alert of high or above |
| SAST         | Semgrep (`p/default`, `p/typescript`, `p/rust`, `p/secrets`)                           | any finding                |
| Dependencies | `pnpm audit --audit-level high`, `cargo audit`, `cargo deny` (licences, bans, sources) | high or critical           |
| Secrets      | Gitleaks on full history; GitHub secret scanning + push protection                     | any finding                |
| Supply chain | OpenSSF Scorecard (weekly, report only)                                                | —                          |

**Hardening:** all third-party actions pinned to a commit SHA; workflow `permissions:` default to `contents: read`; lockfiles committed and installs run frozen; Dependabot for npm, cargo and GitHub Actions (weekly, grouped).

**Scope notes:** CodeQL also scans the workflow files (`actions` language). `cargo deny` checks only the shipped target (`x86_64-pc-windows-msvc`), so Linux-only crates such as `glib` are out of scope; `cargo audit` still reports them as warnings.

## Consequences

- CI runs on Windows runners only (the target platform); slower but avoids cross-platform surprises.
- Some gates (CodeQL Rust, Scorecard) need the repo to be public on GitHub before they run.

**End-to-end tests run locally, not in CI.** WebView2 does not start on GitHub-hosted Windows runners (the app process runs but the web engine never initialises; most likely because jobs have no interactive desktop session). The Playwright smoke test (`pnpm e2e` after `pnpm tauri build --debug --no-bundle`) is therefore a required step in the release checklist, run on a desktop before each tag. Revisit if a self-hosted or GUI-capable runner becomes available.
